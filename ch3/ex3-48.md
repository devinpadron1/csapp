# Exercise 3.48

The functions intlen, len, and iptoa provide a convoluted way to compute the number of decimal digits required to represent an integer. We use this to study aspects of GCC's stack protector facility.

~~~c
int len(char *s) {
    return strlen(s);
}

void iptoa(char *s, long *p) {
    long val = *p;
    sprintf(s, "%ld", val);
}

int intlen(long x) {
    long v;
    char buf[12];

    v = x;
    iptoa(buf, &v);
    return len(buf);
}
~~~

The following show portions of the code for intlen, compiled both with and without stack protection.

Without a protector:

~~~asm
intlen:
    subq $40, %rsp
    movq %rdi, 24(%rsp)
    leaq 24(%rsp), %rsi
    movq %rsp, %rdi
    call iptoa
~~~

With a protector:

~~~asm
intlen:
    subq $56, %rsp
    movq %fs:40, %rax
    movq %rax, 40(%rsp)
    xorl %eax, %eax
    movq %rdi, 8(%rsp)
    leaq 8(%rsp), %rsi
    leaq 16(%rsp), %rdi
    call iptoa
~~~

For both versions:

1. What are the positions in the stack frame for buf, v, and, when present, the canary value?
2. How does the rearranged ordering of the local variables in the protected code provide greater security against a buffer overrun attack?
